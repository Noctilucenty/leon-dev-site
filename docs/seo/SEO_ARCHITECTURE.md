# Leon Builds search acquisition architecture

## Keep the working split

`freelance2` source → reviewed static `homepage/` export → `leon-dev-site` publisher → Render `dist/` → `leonbuilds.org`.

The public service, industry and guide content is generated by `tools/build_pages.py`. The separate intake/events API remains on its existing host and `main` branch. This work does not replace hosting, touch durable lead storage, or edit compiled homepage assets.

## One buyer intent, one canonical destination

The canonical service URL owns the hiring question. A decision guide may own a genuinely different question about choosing a solution; related phrasings belong to that guide, not separate pages. Translations are a distinct audience, with existing reciprocal hreflang retained. No city-specific doorway pages.

Current ownership data: `content/seo/topics.json`. The first 12 mapped concepts cover the nine services, the buyer guide, contractor inquiry guide and missed-lead service. The rest of the existing inventory remains explicitly unmapped until reviewed; mapping the first batch does not mean all 50 URLs have a complete semantic model.

## Publishing boundaries

`content/seo/publication.json` records the 49 verified legacy routes and individually reviewed additions. An added route must have an INDEX decision, ten editorial dimensions of at least 9, a rationale, review date and source hash. Both the page generator and static publisher enforce this gate. A modified source fails until reviewed again. Existing legacy pages are not retrospectively assigned fake scores.

Current structured data uses visible Article/WebPage/BreadcrumbList information for the new guide, with named author, original/updated dates, answer abstract and actual evidence links. It adds no FAQ rating or “GEO schema.” Existing metadata and public identity remain unchanged.

## Discovery and conversion

The service hub and the website, automation and custom-software pages link to the decision guide with context. The guide links to actual project evidence and the contractor inquiry self-audit, then to the existing free-review path. This is a small, useful relationship graph, not an all-to-all link block.

Existing `assist.js` captures first/last attribution and first-party events. New links use `seo_related_click`; the guide CTA uses `seo_guide_review_click`. These are diagnostic interactions, not accepted leads. The existing receipt-backed inquiry, booking UID and authoritative lifecycle stages remain the conversion sources.

## Measurement layer

An offline import accepts a joint Query + Page Search Console CSV with a specified date window. It produces impression-weighted positions, correctly aggregated CTR and review candidates. It never joins unrelated aggregate query/page exports, calls an API, publishes content or writes a client record.

Do not collect raw browser search terms, user contact data or arbitrary referrer paths for this work. Imports filter obvious contact-like queries and remain outside the public allowlist. Reports are not publicly served.

## Next architecture changes need evidence

A guides hub is premature with two guides. Site search, embeddings, a vector database, automated article generation and an interactive scoping application are not needed for this first release. Expand only after repeated buyer questions or dated query data demonstrate their value.
